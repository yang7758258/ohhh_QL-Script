# 龙湖天街 签到脚本（青龙面板版）

> 每日自动签「小程序」+「APP」两个入口，token 每天自动续期 30 天，导入一次凭据后不用再抓包。
> 参考实现：ken861222/longhu-checkin（Python/FastAPI 版，https://github.com/ken861222/longhu-checkin），
> 本项目只取算法与协议结论，代码全部重写成单文件 Node 脚本，零第三方依赖。

**从仓库下载这几个就够跑：**

```text
longhu_signin.js            主脚本（必需）
longhu_dxrisk.js            指纹模块（必需，主脚本 require 它）
sendNotify.js               推送模块（青龙自带同名文件时可跳过）
```

**要取 token 再拿一个：**`龙湖取Token.exe`（手机号 + 短信验证码，无需抓包）或 `grab_longhu_token.js`（从 HAR/cURL 抠）。

> 部署到青龙：脚本管理 → 新建两个文件（`longhu_signin.js`、`longhu_dxrisk.js`）→ 环境变量填 `longhu_token` → 定时任务 `10 8 * * *`。详见第五节。
>
> ⚠️ `longhu_dx_cache.json`（指纹缓存）、`longhu_token.json`（token 账本）、`取Token-设置.json`（含青龙密码）、`取Token-指纹.json`（手机号账本）都是**本机运行产物，含敏感数据，不要提交、不要外传**。

| `longhu_push` | 否 | `on` | on / off / dry（只打印不发） |

| `longhu_delay` | 否 | `5-15` | 多账号随机间隔（秒） |

## 三、怎么拿到 longhu_token（只需一次）

token 有效期 30 天且**滑动续期**，拿一次就够；只有连续停机超过 30 天才需要再来一次。两条路，选一条。

### 方式 A：用 exe（手机号 + 验证码，推荐，多号友好）

双击 `龙湖取Token.exe`（界面长什么样见仓库根 `预览-取Token界面.png`）：

1. 填手机号（备注可留空，默认用脱敏手机号），点右边「获取验证码」；
2. 填收到的验证码 → 回车或点「登录并校验」；
3. **剩下的自动完成**：校验 token → 续期 30 天 → 写青龙 `longhu_token` + `longhu_dx` → 回读确认 → 清场等下个号。

界面上的三件事值得知道：

| 元素 | 作用 |
| --- | --- |
| 「机型 · 随机」按钮 | 点一下换机型预设（随机 / pixel7 / xiaomi14 / oneplus12 / vivo_x100 / samsung_s24），会自动记住 |
| 「随机设备指纹」开关 | 关掉就按手机号稳定派生（不落账本），开着就每号一台独立设备 |
| 胶囊右边的 ⟳ | 给当前号**换一台设备**（重新随机指纹，旧指纹作废，记得同步 `longhu_dx`） |
| 右上「设置」 | 青龙地址/账号/密码，以及三个开关：写 `longhu_dx`、写本地 json、登录后自动写入 |

发码后按钮会变成「重新发送 58s」倒计时，避免手快撞上服务端频控；窗口无边框、可按住标题拖动，Alt+F4 或右上 ✕ 关闭。

exe 自带三个自检入口（出问题先跑它们，别猜）：

```powershell
cd "(解压目录)"
.\龙湖取Token.exe --selftest "$env:TEMP\a.txt"   # 指纹/签名对拍 + 活体校验 + 布局体检
.\龙湖取Token.exe --qltest   "$env:TEMP\b.txt"   # 真青龙上验写入语义（自建临时变量，跑完自删）
.\龙湖取Token.exe --shot     "预览.png"            # 渲染界面 + 查越界压盖
```

**随机指纹是怎么回事**：勾选后每个手机号分到一台独立设备（随机盐 + 随机机型），账本存在
exe 同目录的 `取Token-指纹.json` 里——**同一个号第二次还用这台设备**，不会每次换个新机（换机会掉信任分）。
真要换设备，点「换一台设备」，然后回青龙把该号的 `longhu_dx` 行同步成新指纹。

> 关于滑块：参考项目说「发码首次必弹顶象滑块（`909001`）」，我实测**不成立** —— 只要带的是
> 自己签发的合法指纹，`sendSmsCodeSecret` 直接回 `code:200`，不弹滑块。
> 但个别风控状态下确实会要求，所以 exe 里留了兜底：真遇到 `909001` 它会起一个本地页面
> （跑龙湖自己的 `dx-captcha` SDK）让你拖一次，通过后自动续上发码流程。

### 方式 B：抓一次包（老办法，适合已经有抓包环境）

1. 手机 App 或微信小程序进一次龙湖会员中心（随便点两下，产生请求）；
2. 用 Reqable / Charles / Stream 抓一个发往 `gw2c-hw-open.longfor.com` 的请求；
3. 取下列任一处（都等价，32 位十六进制）：
   - 请求头 `X-LF-UserToken`
   - 请求头 `lmToken` 或 `token`
   - 响应体里的 `data.token`
4. 一条命令搞定（自动抠、自动校验、自动写青龙）：

```powershell
cd "(脚本目录)"
node grab_longhu_token.js "D:\抓包\longhu.har" --deploy
```

没有 HAR 也能用：把抓包工具里那条请求「复制为 cURL」，存成 `curl.txt` 再传进去。

## 四、本地运行

```powershell
cd "(脚本目录)"
$env:longhu_token = "主号#a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6#pixel7"
$env:longhu_push  = "dry"     # 只打印推送内容，先不真发

```

先跑只读探针（不消耗签到机会）：

```powershell
cd "(脚本目录)"
node _probe_longhu.js <32位token>
```

## 五、青龙部署

一键：

```powershell
cd "(脚本目录)"
python deploy_longhu.py --run
```

它会做五件事并逐项校验：

1. 上传 `longhu_signin.js`、`longhu_dxrisk.js`（回读比对内容一致）；
2. `sendNotify.js` 青龙已有就不动；
3. 变量 `longhu_token`：有 `longhu_token.json` 就按 token 去重合并写入，没有就保持面板原值；
4. 建任务「龙湖天街签到」，`task longhu_signin.js`，进度 `10 8 * * *`，并 enable；
5. `--run` 时立刻试跑一次并打印青龙日志。

手工部署（不想跑脚本）：

1. 脚本管理 → 新建，文件名 `longhu_signin.js`，粘贴 `longhu_signin.js` 全文；
2. 同法再建一个 `longhu_dxrisk.js`（**必须**，主脚本要 require 它）；
3. 环境变量按「二」填 `longhu_token`；
4. 定时任务：名称 `龙湖天街签到`，命令 `task longhu_signin.js`，`10 8 * * *`。

## 七、常见问题

**Q1：报 `801810 / 8040012 网络故障，请稍后再试`？**
文案是假的，这是风控。去 App 里**手动签一次并把滑块拖到底**，只拖一次，之后脚本用同一份指纹就能自动签。
**千万别**反复换指纹试探（天天开 `longhu_dx_fresh=on`、或反复删缓存），那会把信任分扣光，反而更签不上。

**Q2：报 `406 token验证出错` / `801001 登录已过期` / `900006`？**
token 过期了，重新抓一个换掉。按第三节走一遍即可。

**Q3：报 `500 小湖忙晕了`，探针也是 500？**
这是**签名密钥失效**，不是 token 问题 —— 龙湖前端改版了。处理办法：到 App 内嵌 H5
`https://supera-h5.wan-prod.longfor.com` 的主 JS 里搜 `getSignHeader`，把新密钥替换
`longhu_signin.js` 里的 `SIGN_SECRET_MICRO_APP`。

**Q4：两个入口都签了，成长值只涨了一份？**
以日历为准：`page-info` 里今日格子 `sign_status=20` 才算签上。脚本对每个入口单独打印结果，
任何一个入口失败都会单独标注，不会互相掩盖。

**Q5：换手机 / 换号需要做什么？**
换号：加一行 `备注#新token`。换机不用管，指纹是从 token 派生的，跟你的设备无关。
只有在**被要求滑块且过不去**时，才 `longhu_dx_fresh=on` 跑一次换新指纹（会消耗一次信任分）。

**Q6：指纹缓存能删吗？**
能，但没必要。删了下次会重新签一份新设备指纹，等于换了台「设备」，风控会重新观察你。
`longhu_dx_cache.json` 里是 42 位指纹，属敏感数据，别外传、别提交到 git。

**Q8：exe 的「随机指纹」和脚本的「按 token 派生」会打架吗？**
不会，优先级是 `longhu_dx`（环境变量）> `longhu_dx_cache.json`（本地缓存）> 当场签发。
exe 勾着「同时写 longhu_dx」时，签到就用 exe 发的那份指纹，登录与签到是同一台设备。
想彻底省事：exe 里把 `longhu_dx` 也写进去，以后别删这一行。

**Q9：exe 支持几个号？**
不限。每号一份指纹、别共用（同一份指纹挂两个号会被判「同一设备多账号」）。
`取Token-指纹.json` 就是账本，删了等于所有号同时换机，别乱删。

**Q7：多账号会互相影响吗？**
不会，一个账号一份指纹（按 token 派生）。同一份指纹挂两个号反而会被判「同一设备多账号」，
脚本在没配 `longhu_dx` 的情况下不会出现这种情况。
